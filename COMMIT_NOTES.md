# What goes in a commit

`.gitignore` enforces most of this automatically. For where data lives and how
calibration works, see `Data/README.md`.

## Commit

| Path | Why |
|---|---|
| `project_config.py` | Resolves every path from `paths.yaml` + `site.json` |
| `Detection/01_detect_Yolo/*.py`, `Detection/02_homography/*.py` | The pipeline code |
| `Detection/03_features/NOTES.md`, `Naming_Behaviors/NOTES.md` | Notes |
| `Data/Data_Config/paths.yaml` | Drive, site and camera selection |
| `Data/Sites/**`: `site.json`, `homo_pick_points.json`, `GogEarth_points.kml`, `H_*_master.npy`, `H_*_first_draft.npy`, `study_area_*.geojson`, `reference_frame.png` | Calibration inputs and results: manual work, small (KB) |
| `Data/footage_manifest.csv` | One row per clip |
| `Data/README.md` | Data and calibration guide |
| `Behaviors/*/config.json`, `Behaviors/*/description.md`, `Behaviors/Sitting/annotations.csv` | Behavior definitions |
| `Detection/03_features/features.csv` | Feature registry (grows as behaviors are deliberated) |
| `Naming_Behaviors/` | Stage placeholders (empty files) |
| `pyenv_requirements.txt` | Python dependencies |
| `.gitignore`, `COMMIT_NOTES.md` | These rules |

## Don't commit (ignored)

| Path | Size | Why |
|---|---|---|
| `*.pt` (YOLO weights) | 190 MB | `yolov8x-pose.pt` exceeds GitHub's 100 MB file limit. Ultralytics downloads weights by name. |
| `Data/Sites/<site>/<cam>/detections/`: detection CSVs, ground/study-area CSVs and GeoJSON | about 50 MB | Regenerated by the scripts (see below) |
| `Data/Sites/<site>/<cam>/checks/`: `check_*` images | small | Regenerated by the scripts |
| `Test/*/Outputs/`: each test notebook's own outputs | varies | Regenerated by the notebook |
| `_to_delete/` | small | Files set aside to delete by hand |
| `.DS_Store`, `__pycache__/`, `.ipynb_checkpoints/` | small | Machine clutter |

## Decide before committing

- **`Test/explore_results/expore_results.ipynb`.** Already committed at 7.2 MB, almost all embedded output images. Run *Clear All Outputs* and save before committing it again, so later versions stay a few KB.
- **`.vscode/settings.json`.** Sets your personal conda setup. It's harmless to share, but only useful to you.

## Not in the repo at all

- **WILDTRACK footage and calibration files.** They live on the drive set by `working_root` in `Data/Data_Config/paths.yaml` (currently `/Volumes/Backup Drive/GSAPP Flash`). The drive must be connected to run any script.

## Regenerating the outputs

Run from your project environment, with the data drive connected. Choose the camera with `camera` in `paths.yaml`.

1. `Detection/01_detect_Yolo/01_detect.py` writes `Data/Sites/<site>/<cam>/detections/detections_<cam>_yolov8m-pose.csv` (with `track_id`) and `checks/check_frames_yolov8m-pose/`.
2. `Detection/02_homography/homography_calibration_imported.py` is the **master** route. It writes:
   - to `Data/Sites/<site>/<cam>/`: `H_<cam>_master.npy`, `study_area_master.geojson` (4 m buffer)
   - to `Data/Sites/<site>/<cam>/detections/`: `detections_<cam>_ground_all_master.csv`, `detections_<cam>_study_area_master.csv`/`.geojson`
   - to `Data/Sites/<site>/<cam>/checks/`: `check_study_area_camera_master.jpg`, `check_study_area_plan_master.png`
3. Optional: `Detection/02_homography/homography_calibration_manual.py` is the **first_draft** route. It writes the same set with a `_first_draft` suffix (2 m buffer).

The two routes use different tags, so they no longer overwrite each other.

Each run overwrites the files with the same name. `Naming_Behaviors/Outputs/` is kept for final outputs only (behavior results).
